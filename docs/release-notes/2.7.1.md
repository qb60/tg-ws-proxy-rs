# v2.7.1

SOCKS5 now forwards destinations outside Telegram's IP ranges as ordinary TCP,
bypassing the Telegram WebSocket/Cloudflare routing ladder. The requested port
is preserved, and the shared outbound connector honors `--outbound-proxy` and
`NO_PROXY`. Hostnames use this TCP path too, with the connector's existing DNS rules.

Mapped DC addresses and destinations inside Telegram's ranges keep their existing
MTProto routing. UDP and BIND remain unsupported. The SOCKS listener remains
unauthenticated, so only trusted clients should be able to reach it.
